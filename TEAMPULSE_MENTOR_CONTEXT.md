## Tech Stack (Final Decisions)

| Layer | Choice | Reason |
|---|---|---|
| Monorepo | Turborepo + pnpm | Best native support, disk-efficient |
| Backend | Node.js + Express + TypeScript | Single backend, no Python microservice |
| AI/LLM | LangChain JS (`langchain`, `@langchain/openai`) | Near-parity with Python for needed chains |
| Database | PostgreSQL 15 (Docker) | Relational, Prisma ORM |
| ORM | Prisma 7 | Schema-first, type-safe client |
| Auth | OAuth2 / session-based (to be implemented) | Proper session management + refresh token rotation |
| Real-time | SSE (Server-Sent Events) | **Not Socket.io** — one-way stream is all that's needed |
| Background jobs | BullMQ + Redis | Job queue for AI pipeline |
| Frontend | Next.js + Tailwind + shadcn/ui | (not started yet) |
| Dev runner | `tsx watch` | Hot-reload in dev |
| Prod build | `tsc` | Compiles to `dist/` |

**Key decisions made and why:**
- **No Python microservice** — LangChain JS handles all AI. Python only needed for spaCy (not in scope); LLM structured prompts replace it.
- **No Socket.io** — digest delivery uses SSE. Socket.io earns its place only if collaborative/multiplayer features are added later.
- **SSE over polling** — cleaner, no extra library, Express supports it natively.

## Architecture Principles (OOP + SOLID + LLD)

### Layer responsibilities — strict boundaries:

| Layer | Responsibility | Must NOT |
|---|---|---|
| **Repository** | Database queries only. Speaks Prisma. | Contain business logic, validation, hashing |
| **Service** | Business logic only. Receives IRepository via constructor. | Touch Prisma directly, know about HTTP |
| **Controller** | HTTP in/out only. Delegates to Service. | Contain business logic |

### Dependency flow:
```
Controller → IService → IRepository → PrismaClient
```

Services receive interfaces (not concrete classes) via constructor injection. This is the Dependency Inversion Principle — high-level modules depend on abstractions.

### Singleton for PrismaClient:
- One instance across the entire app
- Prevents connection leaks on `tsx` hot-reload
- `globalThis` cache prevents multiple instances in development
- In production: skip the global cache (process restarts cleanly)

## Key Concepts the Mentee Has Learned

- `^` in `turbo.json` `dependsOn` means "run this task in all dependency workspaces first"
- `app.ts` vs `server.ts` split — testability (import app without opening a socket)
- `tsx watch` for dev (runs TS in memory, hot-reloads) vs `tsc` for production build (compiles to disk)
- `switch(boolean)` is a code smell — ternary is cleaner
- Redundant `dotenv.config()` calls — env loading should happen once
- Singleton pattern for PrismaClient — prevents connection leaks on hot-reload
- Repository = DB queries only, Service = business logic only, Controller = HTTP only
- `prisma` (CLI) = devDependency, `@prisma/client` (runtime) = dependency
- Migrations path should be `prisma/migrations`, not inside `src/`
- Side effects like `process.exit(1)` don't belong in module files — only in bootstrap (`server.ts`)
